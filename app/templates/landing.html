Safe-Testing Principles & Platform Boundaries

Security testing requires strict authorization and rigorous isolation. This platform enforces three core guarantees:

  • Isolated Lab Environment: All vulnerable scenarios run within sandboxed routes with synthetic data. Production and admin assets are physically isolated.
  • Built-in Lab vs. External Targets: The lab operates entirely on local controlled scenarios by default. Optional external testing requires explicit administrator approval and strict RFC 1918 private-IP blocklists.
  • Zero Harmful Payloads: Every test action uses benign, non-destructive payloads designed for educational verification without weaponization.

The Five-Stage Security Cycle

A structured engineering discipline from discovery through confirmed verification.

01. Define

Establish preconditions, test scope, and baseline expectations using standard presets.

02. Test

Execute safe browser-level actions with execution lifecycle state tracking and timeouts.

03. Observe

Collect sanitized evidence records tagged with provenance: Observed Live, Controlled, or Simulated.

04. Interpret

Classify findings objectively into Confirmed, Potential, Inconclusive, or Simulated states.

05. Remediate

Apply atomic code fixes, capture before/after states, and re-verify remediation outcome.

The Ten Web Security Checks

Standardized tests from the Web Security Testing browser methodology.

01. Robots.txt Enumeration

Information Disclosure

Discovering hidden endpoints and sensitive folders disclosed in robots.txt without access control.

02. URL Parameter Tampering & IDOR

Broken Access Control

Manipulating identifiers to access unauthorized records when server-side authorization checks are missing.

03. Directory Guessing / Forced Browsing

Access Control

Directly browsing predictable administrative, diagnostic, or backup resources without authorization.

04. Cookie Inspection

Session Management

Verifying security flags: HttpOnly prevents XSS theft, Secure enforces HTTPS, and SameSite blocks CSRF.

05. HTTPS & Certificate Check

Transport Security

Checking TLS certificate validity, cryptographic cipher suites, and automatic plaintext HTTP redirection.

06. Form Input Validation & XSS Awareness

Injection Defense

Auditing client vs. server-side input sanitization, HTML entity encoding, and Content-Security-Policy.

07. Inspect Page Source & Client-Side Code

Sensitive Exposure

Uncovering hardcoded API keys, developer comments, and sensitive internal endpoints in client assets.

08. Network Tab: What Is the Site Sending?

Data Minimization

Analyzing REST API payloads for over-fetching and excessive personal data disclosure.

09. Default & Weak Credential Testing

Identification & Auth

Testing default accounts, weak complexity rules, and lockout enforcement against brute force.

10. Error Message Analysis

Information Disclosure

Evaluating unhandled exceptions to prevent stack trace leaks, database schemas, and absolute system paths.
